# 团队能力盘点规范

产出任何"能力盘点"类记忆时，必须按以下三级口径如实分级，禁止夸大或含糊：

## 三级口径
1. **能力 ✅**：已在本环境实测验证过或属核心强项的能力，需附验证证据（项目/实测记录）
2. **受限 ⚠️**：可产出代码/方案但无法在本环境长期运行或实测的部分，需写明缺失的资源（服务器/代理/账号/key 等，属用户侧配套）
3. **不可为 ❌**：环境或法律边界内明确做不到的，需写明原因

## 格式要求
- 逐环节对照，不写笼统的"我们很强"
- 结尾给一句话总结：哪些我方全包、哪些需用户侧配套
- 已建立的先例：世界盒子逆向能力盘点、知乎 API 逆向能力盘点（可后续入库 topics/ 作参照）
